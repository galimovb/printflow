# Термонаклейки

Отдельный товар `thermo` в общем приложении printflow, артикулы `TRM-`.
Один вариант `main` на дизайн. Свои счётчики, группы, очередь и бакеты S3:
`trm-print`, `trm-mockups`, `trm-high-resolution-prints`.

Поддерживаются общий API `/api/v1/thermo/jobs`, пакетная постановка, импорт XLSX,
тематики и идеи, возобновление по этапам, повторы Ozon, объединение дизайнов,
сертификаты и hi-res при заказе. Принт из фото сначала извлекается генератором;
галерея затем строится локально без дополнительных запросов генерации изображений.

## Галерея

Единый генератор поддерживает `assortment.mode`: `single` (1 принт) и `set`
(одинаковый рисунок в 2–6 размерах). В рабочей выгрузке активен одиночный принт шириной 21 см с пропорциональной высотой.
В `assortment.sizes` можно задать список `{key, label, size_cm: [ширина, высота]}`.
Если список не задан, режим set использует прежний `set_sizes`, single — `single_size_cm` (21 × 29,7 см, ширина × высота).
Размеры положительные, в сантиметрах, от меньшего к большему.

Всегда шесть слайдов: главная, футболка, шоппер, размеры/состав, перенос и уход.
Для одиночного принта главная показывает сам рисунок с бейджем размера,
слайды 2–3 — по одной вещи, слайд 4 — принт с размерными стрелками. Для набора на слайдах 2–3 одинаковые вещи стоят в ряд
(4–6 размеров — в два ряда). Меняется размер принта, масштаб вещей общий.
Подписи, количество, название, описание и rich-контент Ozon рассчитываются
из одного состава. Если изменилось количество после подготовки характеристик
Ozon, публикация требует повторить `ozon_prepare_card --product thermo`.
Габариты упаковки и цена задаются отдельно.

Примеры полной локальной сборки пустых и готовых карточек на общих шаблонах:

```powershell
.venv/Scripts/python.exe -m printflow.products.thermo.scripts.generate_blanks --check-only --mode single --sizes 21x29.7 --print outputs/thermo-full-cycle/butterfly-print.png --output-dir outputs/thermo-universal/single
.venv/Scripts/python.exe -m printflow.products.thermo.scripts.generate_blanks --check-only --mode set --sizes 6.5x9.5 10x14.6 13x19 --print outputs/thermo-full-cycle/butterfly-print.png --output-dir outputs/thermo-universal/set
```

`--output-dir` отделяет результат сборки от исходных шаблонов в `--out-dir`.
Без `--check-only` выполняется существующий цикл генерации четырёх сцен GPT,
после чего тот же сборщик создаёт выбранный режим. При обычной смене рисунка
или комплектации новые изображения GPT не нужны. Параметры `--mode` и
`--sizes` также доступны в `scripts.preview_gallery`.
`resolved-product.json` рядом с результатом фиксирует выбранный состав и тексты.
Параметры CLI действуют только на текущую сборку; для рабочего конвейера
сохраните состав в `config/product.json → assortment`.

Фон голубой, акценты кобальтовые. GPT создаёт только пустые шаблоны вещей.
**Все тексты и размеры вставляются затем кодом настоящими шрифтами.**
Текущий PNG-принт накладывается на каждую вещь локально; никаких пантер
или надписей в рабочем шаблоне нет. Футболка на главной композиции разглажена.
Все нижние белые бейджи имеют общие координаты (65,1390)–(1135,1515);
подписи размеров выравниваются по центру объектов с зазором 32 px.
Никаких новых запросов GPT при обычной сборке галереи товара не требуется.
Шрифты, тема, математика наложения и каркасы собственные; другие товары не импортируются.

Локальное превью производственного генератора, без сети:

```powershell
.venv/Scripts/python.exe -m printflow.products.thermo.scripts.preview_gallery --print path/to/print.png
```

Старый запуск `python -m scripts.generate_thermo_mousepad_cards` вызывает этот же код.
Образец пантеры используется только при запуске превью без `--print`.
Обложка по умолчанию содержит общие подписи, без обещания камней или настоящей вышивки
для произвольного принта; подписи меняются в `config/product.json → texts`.

## Подготовка к реальной выкладке

1. Настройки `THERMO_*` добавлены в локальный `printflow/.env`, `thermo` добавлен
   в `SM_PRODUCTS`. Кабинет не копируется с другого товара автоматически. Заполните
   `THERMO_OZON_CLIENT_ID`, `THERMO_OZON_API_KEY`; токен API отдельный.
   Ключи THERMO_* — в printflow/.env.
2. В `config/product.json → ozon` задайте цену, габариты упаковки в мм, вес в г, при необходимости
   НДС, старую цену, себестоимость, склад и остаток. Нулевые/неизвестные размеры не публикуются.
3. Получите категорию и характеристики из справочника кабинета (только чтение API Ozon):
   `python -m printflow.scripts.ozon_prepare_card --product thermo`.
   При неоднозначном типе задайте точные `--category` и `--type` из отчёта.
   Добавьте обязательные характеристики в `ozon.wishes` и повторите подготовку.
4. Создайте бакеты: `python -m printflow.scripts.create_buckets --product thermo`.
5. Пересоберите и перезапустите приложение штатным Docker Compose после настройки.
   Новые каркасы, product.json и themes.json подключены как отдельные тома.
6. Проверяйте постановку с `dry_run: true`, затем используйте существующий
   `publish_dry_runs --product thermo`. Dry-run не отправляет карточки в Ozon,
   но генерация принта и сохранение в S3 выполняются штатно.

Реальная задача без категории, цены, веса, габаритов и цвета завершается понятной
ошибкой ДО платной генерации. Значения коммерческих параметров не выдумываются.
При заказе hi-res сохраняется в собственный бакет; повторный заказ использует готовый файл.

Тесты: `python -m unittest discover -s printflow/tests -p "test_*.py"`.

## Генерация всех шаблонов одним запуском

```powershell
.venv/Scripts/python.exe -m printflow.products.thermo.scripts.generate_blanks
```

Используются только настройки `THERMO_*` и общие настройки клиента OpenAI.
Четыре запроса GPT с общим стилем: голубой фон, сцена с футболкой,
сцена с шоппером и пустая композиция из трёх вещей (`accents-scene.png`).
Тексты, плашки, стрелки и принт в GPT-шаблонах отсутствуют.
Код добавляет текст и рисунок после генерации. Для трёх сравнительных
мокапов из свежих сцен выделяются прозрачные каркасы `shirt-transparent.png`
и `shopper-transparent.png`. Масштаб записывается в `mockup-calibration.json`;
пустые поля вырезаются после наложения принта. Старые каркасы не копируются.
Полные сцены остаются резервным способом рендера,
если прозрачного каркаса нет. Все шесть пустых макетов экспортируются в `cards/`.

Сцены: `background-scene.png`, `shirt-scene.png`, `shopper-scene.png`,
`accents-scene.png`. Последняя обязательна для главной карточки.
Пустые поверхности сцены и перспективные зоны в `gallery.accents` должны совпадать;
после перегенерации нужно визуально проверить наложение и при необходимости
скорректировать зоны. Для отдельного набора шаблонов можно сохранить
`accents-calibration.json` с зонами shirt/shopper/pouch: рендерер отдаёт ему
приоритет перед `product.json`. Скрипт не угадывает положение ткани по новой фотографии.

Запуск из другой папки и режимы:

```powershell
.venv/Scripts/python.exe -m printflow.products.thermo.scripts.generate_blanks --out-dir outputs/thermo-scenes-check --quality medium
.venv/Scripts/python.exe -m printflow.products.thermo.scripts.generate_blanks --dry-run
.venv/Scripts/python.exe -m printflow.products.thermo.scripts.generate_blanks --check-only
```

`--dry-run` записывает точные промпты и план без сети. `--check-only` проверяет
готовые сцены и собирает превью без запросов GPT. `--only shirt shopper` обновляет
выбранные сцены, остальные должны уже существовать в папке результата.
`--resume-from <папка _generation/ID>` повторно проверяет уже полученные GPT-ответы
и завершает установку без новых запросов. Проверка не пропускает одежду, которая
заходит в область заголовка.
Новые файлы сначала проверяются во временной подпапке `_generation`; утверждённые
шаблоны заменяются только после успеха всех шагов, старые сохраняются в `_backups`.
В `generation-report.json` сохраняются модель, результаты проверки и список макетов.

Требуется установленный CLI навыка imagegen (`$CODEX_HOME/skills/.system/imagegen/scripts/image_gen.py`)
либо путь `--imagegen-cli`. Это общий клиент генерации, а не модуль другого товара.
Ключ и базовый адрес читаются из конфигурации приложения и передаются CLI через окружение.
Остальные товары не импортируются и не изменяются при запуске этого скрипта.

## Масштаб наклеек на вещах

Малый, средний и большой принты на слайдах 2–3 рассчитываются отдельно
из `set_sizes`. Опорная ширина футболки — 52 см, шоппера — 34 см;
параметры каркасов находятся в `gallery.mockups`.
Главная композиция использует реальные размеры плоскостей ткани
`surface_cm` и их перспективные четырёхугольники `surface` в `gallery.accents`.
Размеры самих принтов проецируются внутрь этих плоскостей в сантиметрах;
отдельного увеличения принта для главной карточки нет.
Рисунок вписывается в каждую область с сохранением пропорций, оттеняя ткань.
Вещи иллюстративные; точные размеры наклеек указаны на первых трёх слайдах.

Рабочие данные термопринтов: `SM_DATA_DIR/thermo/reports`.
Локальное превью без `--out` сохраняется в `data/thermo/preview`.
Другую папку для экспорта можно указать явно через `--out`.

### Три вещи в один ряд

Слайды 2 и 3 показывают три целые одинаковые вещи в один ряд, слева направо:
малый, средний, большой принт. Масштаб вещи и линия низа общие; подписи
имеют одинаковые размеры и отступ 32 px. Параметры ряда:
`gallery.comparison_row` в product.json. Фрагментов и увеличения отдельных
участков ткани нет.

Один скрипт генерирует шаблоны, добавляет текст шрифтами и опционально наносит
выбранный PNG, экспортируя шесть готовых PNG/JPEG и архив:

```powershell
.venv/Scripts/python.exe -m printflow.products.thermo.scripts.generate_blanks --print outputs/thermo-full-cycle/butterfly-print.png
```

Для пересборки с уже созданными шаблонами без новых запросов GPT добавьте
`--check-only`. Пустые карточки находятся в `cards/`, готовые в `ready/`,
общее превью — `ready-preview.jpg`, архив — `ready-six-jpg.zip`.

## Текущая рабочая выгрузка: один принт A4

API и импорт XLSX не требуют выбора комплектации. Новые задачи thermo получают
один принт шириной 21 см и высотой по пропорциям рисунка. Набор из трёх размеров остаётся
доступен только для подготовки шаблонов через `generate_blanks --mode set`.

Состав и размеры фиксируются в задаче при постановке. Повтор после ошибки
использует сохранённую конфигурацию. Ещё не заполненные коммерческие поля
черновика можно заполнить позже: перед реальной публикацией они проверяются.
Цена, упаковка и подготовленные характеристики одиночного предложения могут
переопределяться в `offers.single.ozon`; незаданные поля берутся из общего `ozon`.

Разные рисунки объединяются общим механизмом групп, как у остальных товаров:
`THERMO_OZON_MERGE_DESIGNS=50`, общее «Название модели» группы, отдельный артикул
TRM-xxxxxx и позиция рисунка в названии цвета. Суффиксов комплектации у групп нет.
Ключи импорта сохранены в формате `ref:<SKU>`, повтор XLSX не создаёт дубли.

Подготовка справочников не создаёт товары на Ozon:

```powershell
.venv/Scripts/python.exe -m printflow.scripts.ozon_prepare_card --product thermo
```

Она сохраняет атрибуты и количество 1 для `offers.single.ozon`.
Перед выкладкой нужно заполнить категорию, тип, цену, габариты и вес упаковки,
а также справочник цвета. Скрипт не выдумывает эти значения.

Импорт отобранного списка в запущенный сервис (генерация и S3 выполняются даже
с --dry-run; этот флаг отключает только публикацию Ozon):

```powershell
.venv/Scripts/python.exe -m printflow.scripts.from_xlsx --product thermo outputs/thermo-single-prints-20261018/thermo-single-prints.xlsx --limit 1 --dry-run
```

Наблюдатель заказов находит задачу исходного артикула и переносит её размеры
в hi-res задачу. Оригинал остаётся в `trm-high-resolution-prints/<article>.png`.
Дополнительно создаются прозрачный PNG 300 dpi
`<article>/300dpi/single.png` (2480 px в ширину, высота по пропорциям рисунка) и `<article>/print-manifest.json`.
При повторном заказе существующий оригинал используется без новой генерации.

## Автоматическая высота одиночного принта

`single_sizing: width_proportional`, `single_width_cm: 21`: после получения
PNG обрезаются прозрачные поля, затем высота считается как
`21 × высота_рисунка_px / ширина_рисунка_px`. Пропорции не изменяются.
`single_size_cm` остаётся предварительным форматом до получения рисунка.

Итог сохраняется в `result.product_config.resolved_print` и `print_dimensions`
до сборки галереи и Ozon. Все надписи, размерные стрелки, масштаб на вещах,
название, описание и rich-контент используют эти размеры. В тексте размеры
округляются до 0,1 см, геометрия и печатный PNG используют точные значения.
Набор из трёх размеров сохраняет прежние фиксированные области.

Наблюдатель заказов берёт итоговую конфигурацию из результата карточки,
а не предварительный формат из запроса. Поэтому высота PNG 300 dpi тоже
индивидуальна, ширина остаётся 2480 px. Старые карточки автоматически
не перезаписываются этой правкой.

Корпус шоппера на мокапе — 34 × 38 см, как в модуле шопперов. Перед
наложением рисунка высота корпуса приводится к этому соотношению сторон;
ширина и высота самого рисунка используют общий масштаб пикселей на сантиметр.
